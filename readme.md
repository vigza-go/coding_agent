# 分层上下文 Coding Agent

一个跑在终端里的编码 Agent：能读写本地仓库文件、执行 shell 命令、维护自己的工作状态。

![alt text](image-1.png)
大部分 Agent demo 解决的是"能不能跑通一次调用"。这个项目想解决的是另一类问题——**当它连续跑上几十轮、改了几十个文件、上下文涨到几十万 token 之后，怎么还不崩、怎么还能撤回去、怎么让成本可观测**。

技术栈：Python · LangGraph · LangChain · SQLAlchemy · MySQL · prompt-toolkit · Rich

```
核心代码约 5.6k 行 ｜ 测试约 5.7k 行 / 240 个 pytest 用例
机制、不变量与推导见 DESIGN.md ｜ 怎么跑见 RUNBOOK.md ｜ 评测在 experiments/
```

```bash
uv sync --extra dev
cp config.example.json config.json      # 填入模型 API key
uv run --env-file .env coding-agent --thread demo
```

TUI 命令：

| 命令 | 作用 |
| --- | --- |
| `/history [N]` | 查看最近 N 条有效消息（`/list` 为兼容别名） |
| `/threads` / `/thread ID` | 列出会话 / 切换会话（目标正被别的会话跑 turn 时拒绝切换） |

| `/help` `/exit` | 帮助 / 退出 |

输入：Enter 发送，Alt+Enter 换行，方向键浏览本次进程内的输入历史。更细的排障与配置见 [RUNBOOK.md](./RUNBOOK.md)。

## 它解决什么

### 1. 上下文分层压缩：一个"2048 式"的记忆结构

```
框架提示词 + 压缩区 + 工作状态便签 + 工作区 + 输出缓冲区
```

默认 1M 窗口：压缩区上限 1/4，工作区涨到 1/2 就先剪裁、剪不出余量才把前缀摘要成 L0 块；块只与**同级**合并，像 2048——**越早的记忆被合并次数越多、越模糊；越近的越清晰**，从o(n)降到o(log n)。比例、切块、合并与摘要上限的口径全在 [DESIGN.md](./DESIGN.md)「上下文布局与压缩」。

分层买到的是"每轮少发 token"（把"摘要的摘要"从线性压成 log 级），**不是更好的信息保留**：实测合并到 L3 后路径类锚点会归零，保真不如同预算下"只留最近"。这个取舍是否划算取决于会话长度——**短会话（压根不触发压缩）两者没有差别**。

### 2. 会变的东西不进历史序列

服务端 prompt 缓存按**前缀逐字节一致**命中，所以成本由"改动落在多前面"决定，"改了多少"不重要。由此推出两条硬规矩：

- **剪裁只在越过触发线那一次做，而且一次做完**（冷思维链削进预算 + 旧工具结果换占位符）。分两步剪等于把断前缀的次数翻倍。被削的是投影，库里仍是原文，可审计。
- **工作状态不每轮注入**。它是模型自己的笔记本（踩过的坑、已确认的事实、临时约束），平时模型自己 `get`；只在剪裁那一刻贴一张便签，两次剪裁之间逐字节冻结——把"模型写入"和"投影变化"解耦。

踩过的坑：工作状态原先是渲染成 SystemMessage 塞进每轮投影的，而 `langchain_anthropic` 会把它提到请求最前（system 字段）——它一变，整条历史从第 0 个 token 起全部重编码，而工具每写一次它就变一次。实测那条线程的缓存命中率因此掉到 93%（其余线程 99%）。

### 3. 一切都能撤回去

文件写在执行前把原始字节存进按 SHA-256 去重的 blob 表并记一条 mutation；`/undo` 停用 `user_seq >= N` 的消息、工作状态与相交的记忆块，倒序还原文件，再从有效的记忆块重建覆盖。固定七步与几处容易做错的取舍见 DESIGN.md「撤销语义」。

一句产品定义：撤销**不检查文件当前 hash**——用户手改过也直接还原。语义是"回到那轮之前的状态"，不是"安全地合并"。

### 4. 长跑不崩：协议自洽与并发

四处会破坏 `assistant.tool_calls` 与 ToolMessage 的严格配对（压缩切分、中断轮次、迟到结果、额度截断），都做了处理，见 DESIGN.md「会话协议自洽」。

同一条 thread 同一时刻只允许一个会话待在里面（MySQL 连接级咨询锁，不建表不加字段，进程死即释放）。缓存只在追加、写状态、压缩这些短操作上按 thread 加锁，**不锁住整个 turn**，并行工具才能真并行。

### 5. 边界说清楚：它不是沙箱

Bash 用 `/bin/bash -lc` 在独立进程组里跑：超时 `killpg` 杀整棵进程树、输出限量、非零退出与超时回传给模型自行修正、不自动重试。

**它不是沙箱**：Bash 全权在，文件工具也是同一套语义——以 `/` 开头就是宿主机真实绝对路径，相对路径基于 workspace root。`FilesystemBackend` 刻意**不开** `virtual_mode`：开着的时候，真实绝对路径会被剥掉前导斜杠、静默写进 `root/Users/apple/...` 这种嵌套目录里（真机踩过一次，**"静默越界"是最坏的失效模式**）。代价是没有 root_dir 沙箱，但 Bash 本来就全权在，本地个人使用下不是实质损失；要隔离请用容器或 Git worktree。V1 不追踪 Bash 造成的文件变更，目录删除直接拒绝。

## 联网搜索（可选）

配置面只有四项（开关、key、超时、条数上限），端点与模型名属于实现内部。当前接的是 DashScope 的**生成期搜索插件**（该服务没有独立搜索 API），实测**只返回标题与 URL、不返回网页正文**——所以工具结果里的 `answer` 出自远端搜索增强模型，需按 sources 自行核验。服务端返回 200 却不给来源是一种静默失败形状，因此"无来源"一律判为失败而非成功。

## 目录结构

```
coding_agent/
├── context/        # token 预算、原子分块、摘要、合并、贪心覆盖重建、派生缓存
├── persistence/    # SQLAlchemy 模型、连接、repository、消息编解码、幂等迁移
├── workspace/      # 工具结果 artifact 落盘、文件 mutation 快照与 undo
├── services/       # 跨领域编排：rollback、调用额度、上下文投影、消息持久化、进度事件
├── integrations/   # LangChain/LangGraph 中间件与 agent 组装、bash 执行、桌面集成
├── application.py  # 用例入口（TUI 只调这一层）
└── ui/             # 终端界面
```

依赖方向：领域/持久化 → service → integration/application → UI。UI 不直接访问 repository；框架中间件不反向进入 context、workspace 等核心模块。

## 测试与评测

240 个 pytest 用例、约 5.7k 行，`uv run pytest -q` 用 SQLite 即可、无需外部数据库。覆盖方向：撤销与一致性、压缩（生成、同级合并、贪心覆盖、摘要失败不改缓存）、剪裁时机与工具窗口、工作状态便签、并发与文件锁、协议补齐与幂等、Bash 边界、成本统计口径。另有 4 个与近期改动无关的既有失败（agent / subagent / tui×2）。

对照评测在 `experiments/`：用 LongMemEval 的真实历史，比较分层摘要与滚动摘要各喂给摘要器多少 token。`lme_timeladder.py` 单题回放（顶部 `FAKE = True` 可零成本检查形状）、`batch.py` 批量选题并发、`report.py` 汇总；跑法与最近一次完整记录见 [experiments/README.md](experiments/README.md) 与 [EVAL_REPORT_2026-09-06.md](experiments/EVAL_REPORT_2026-09-06.md)。

## 已知限制

诚实列出，都是有意为之的边界而非疏漏：

1. **短任务下压缩基本不激活**：1M 窗口 + 500k 触发线，几十轮以内的普通任务根本不会压缩，分层收益只在长会话、多次压缩后才显现。合并**确实已经在真实长会话里发生过**（09-04 实测：26 分钟内 12 次，层级到 L3），但"发生"不等于"有益"——等预算下合并产物的锚点保留率并不优于只留最近的摘要。
2. **缺真实摘要器的端到端质量数据**："同一任务在不同预算档位下成功率对比"还没有，这是下一步最该补的一块。
3. **多进程同一 thread 只能轮流，不能并行**：占用锁跨进程有效（进入即占用，空着不说话也挡人），但**读侧仍是进程内缓存**——别的会话提交的轮次不会主动通知我，只能靠写轴前的 seq 分歧检测兜住，多机部署仍需固定路由或分布式失效通知；SQLite 下没有这把锁。
4. **Bash 造成的文件变更不可撤销**，目录删除在 V1 中拒绝执行。
5. **token 数是本地估算**，与 API 实际计费存在偏差，阈值触发点会偏；正式做法是用 API 返回的 usage 校准。
6. **摘要调用的用量未计入 `/usage`**（摘要走独立路径、不经过消息持久化），拿它比较两种压缩算法的总成本会偏低。
7. **无流式输出**：最终回答等模型全部生成后才整段打印，长回复时用户要干等。
8. **便签会滞后于最新一版工作状态，而且没有体积上限**：它只在剪裁时刷新，所以"写完、还没剪裁"那段窗口里投影里那张是旧的（工具描述已写明以 `get` 为准）。另有一条**尚未实测**：模型会不会把便签当成新指令去回应——目前只有提示词层面的防线。
9. **撤销会在历史中间挖空，其后所有缓存前缀一并失效**（实测一次 39k token 的 miss）：软删除语义的直接代价，V1 接受。
